# job-finder

Локальный MCP-помощник для поиска вакансий на hh.ru, подготовки сопроводительных писем и ответов рекрутерам. Интеграция обращается только к официальному API hh.ru; браузерный скрейпинг, автокликер и обход капчи отсутствуют.

Проект специально разделяет подготовку и внешнее действие:

1. Поиск, ранжирование и генерация черновиков можно выполнять автоматически.
2. Отклик или сообщение сначала создаётся как предпросмотр с одноразовым `confirmation_id`.
3. Отправка возможна только второй командой после явного согласия пользователя на конкретный текст.

## Что умеет

- искать вакансии несколькими запросами и удалять дубликаты;
- давать объяснимый локальный скоринг соответствия и отмечать пробелы;
- подбирать релевантные фрагменты из личной базы знаний;
- готовить контекст, по которому Codex пишет сопроводительное строго по памятке;
- читать актуальные чаты `/common/chats` и готовить ответы на вопросы рекрутера;
- отправлять отклики и сообщения через двухшаговое подтверждение;
- останавливать любые отправки при капче, HTTP 429 и лимитах hh.ru.

## Быстрый запуск

Требуется macOS и Python 3.11+.

```bash
cd /Users/macos/job-finder
python3 -m venv --system-site-packages .venv
.venv/bin/python -m pip install --no-build-isolation -e .
.venv/bin/job-finder status
```

Локальный `config.toml` уже указывает на:

- `/Users/macos/Downloads/baza_znaniy_opyt.md`;
- `/Users/macos/Downloads/baza_keysov_interview.md`;
- `/Users/macos/Downloads/pamyatka_soprovoditelnye.md`.

Файл исключён из Git. Сами базы знаний не копируются в репозиторий.

## Авторизация hh.ru

Предпочтительный вариант — OAuth2 с PKCE:

1. Создайте приложение в [кабинете разработчика hh.ru](https://dev.hh.ru/admin).
2. Укажите callback: `http://127.0.0.1:8765/callback`.
3. Выполните:

```bash
.venv/bin/job-finder auth configure
.venv/bin/job-finder auth login
.venv/bin/job-finder auth test
```

`client_secret`, `access_token` и `refresh_token` сохраняются в macOS Keychain через системный Security.framework и не передаются аргументами командной строки. Пароль от hh.ru приложению не нужен: официальный OAuth выдаёт доступ без получения логина и пароля пользователя. Поддерживаются `state`, PKCE S256 и только фиксированный loopback callback. См. [официальную документацию авторизации hh.ru](https://api.hh.ru/openapi/redoc#section/Avtorizaciya/Avtorizaciya-polzovatelya).

Если готовый токен уже есть, его можно ввести локально, скрытым вводом:

```bash
.venv/bin/job-finder auth import-token
```

Не вставляйте токен в чат, `config.toml`, `.env` или Git.

## Подключение к Codex

```bash
codex mcp add job-finder -- /Users/macos/job-finder/.venv/bin/job-finder-mcp
codex mcp get job-finder
```

После подключения начните новую сессию Codex. Примеры запросов:

- «Найди свежие релевантные мне вакансии в Москве и покажи топ-15»;
- «Подготовь сопроводительное к вакансии 123456789»;
- «Покажи непрочитанные чаты и напиши ответ на последний вопрос»;
- «Подготовь предпросмотр отклика, но не отправляй»;
- «Отправь именно этот показанный отклик».

## Инструменты MCP

Чтение и подготовка:

- `status`;
- `discover_vacancies`;
- `get_vacancy`;
- `list_my_resumes`;
- `prepare_cover_letter`;
- `list_chats`;
- `get_chat_messages`;
- `prepare_chat_answer`.

Запись, всегда двумя шагами:

- `prepare_application` → `submit_application`;
- `prepare_chat_message` → `submit_chat_message`.

Новые чат-методы и поле `is_automated` взяты из [актуальной спецификации HeadHunter API](https://api.hh.ru/openapi/redoc#tag/Chaty). Сообщения, созданные с помощью AI, всегда отправляются с `is_automated=true` и UUID-ключом идемпотентности.

## Защита от блокировки

- Только `https://api.hh.ru`, без приватных web-endpoint’ов hh.ru.
- Нет Selenium, Playwright, подмены fingerprint, прокси-ротации или обхода капчи.
- Не более 8 поисковых запросов за один вызов и не более 20 результатов на запрос.
- Между чтениями минимум 0,8 с; между отправками минимум 10 с.
- Локальный предел по умолчанию: 10 откликов и 30 сообщений в сутки. Это консервативные настройки приложения, а не заявленные лимиты hh.ru.
- `captcha_required`, `limit_exceeded`, `overall_limit`, HTTP 429 и неопределённый сетевой исход write-запроса включают постоянный safety-stop. Автоповтора нет.
- Повторное использование подтверждения невозможно; отклики локально дедуплицируются по паре вакансия + резюме.
- Для чата используется официальный idempotency key.

После ручной проверки аккаунта safety-stop снимается только локально:

```bash
.venv/bin/job-finder safety clear-stop
```

Коды ошибок и ограничения откликов документированы в [официальном справочнике ошибок hh.ru](https://github.com/hhru/api/blob/master/docs/errors.md).

## Конфиденциальность

MCP-сервер, HTTP-клиент, база состояния и Keychain работают локально. Однако при использовании с облачной моделью Codex выбранные фрагменты вакансии и базы знаний попадают в контекст модели для генерации текста. Токены, `client_secret` и заголовки авторизации в этот контекст не выводятся.

Локальная SQLite-база хранится в `state/job-finder.sqlite3` с правами `0600`; в ней есть предпросмотры и журнал отправок. Каталог `state/` исключён из Git.

## Проверка

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Проект не содержит сторонних runtime-зависимостей: MCP stdio, HTTPS, OAuth и Keychain реализованы средствами стандартной библиотеки Python и macOS.
