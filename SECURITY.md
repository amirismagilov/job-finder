# Security policy

## Модель угроз

Главные риски для этого проекта: утечка OAuth-токена, случайная массовая отправка, повторная отправка при сетевой неопределённости, обход правил hh.ru и публикация персональной базы знаний.

Принятые меры:

- секреты — только в macOS Keychain;
- транспорт MCP — локальный stdio, без постоянно открытого HTTP-порта;
- OAuth — `state`, PKCE S256, фиксированный loopback redirect;
- любые записи — двухшаговые, с короткоживущим одноразовым подтверждением;
- чат — официальный UUID idempotency key и `is_automated=true`;
- нет автоматических повторов write-запросов;
- жёсткая остановка на капче и лимитах;
- `config.toml`, `state/`, `.env` и приватные файлы исключены из Git.

## Что не следует добавлять

- браузерную автоматизацию hh.ru;
- приватные endpoint’ы сайта вместо публичного API;
- обход капчи или антибот-механизмов;
- логирование HTTP-заголовков и OAuth-ответов целиком;
- безусловный auto-submit;
- передачу токена через аргументы командной строки или MCP tool output.

## Сообщение об уязвимости

Не публикуйте реальные токены в issue. Сначала отзовите токен в hh.ru, затем сообщите только минимальный воспроизводимый пример без персональных данных.
