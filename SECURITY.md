# Security policy

## Граница доверия

Backend не получает Cookie, CSRF, browser headers или произвольный URL. Pairing secret предъявляется расширением только фиксированному `127.0.0.1:8766` и сравнивается постоянным временем. При первом корректном запросе bridge привязывается к `chrome.runtime.id`; другой extension origin отклоняется.

Расширение строит метод, origin, path, query и body из собственной закрытой таблицы. Команда backend содержит только action enum и проверенные бизнес-параметры. CSRF читается и используется внутри браузерного content script и никогда не сохраняется. Сырой HTML и исходный JSON тоже не покидают браузер: action-specific projector возвращает только типизированные allowlisted-поля, а backend повторно проверяет всю nested-схему.

## Секреты и персональные данные

- Pairing secret и LLM API key — только macOS Keychain или `chrome.storage.local`; они не принимаются через argv и не выводятся в логи.
- Cookies остаются в browser cookie jar. Расширению не выдано разрешение `cookies`.
- `config.toml`, `state/`, HAR и базы знаний исключены из Git.
- SQLite и его каталог получают права `0600`/`0700`.
- Аудит принимает только известную metadata, удаляет чувствительные ключи и не хранит bridge payload.
- Модель не получает session credentials, команды сети, pairing secret, API key, идентификаторы или URL.

Исходные `/Users/macos/Downloads/hh.ru.har` и `hh.ru1.har` использовались только для локального анализа имён методов/полей. Они не копируются в проект. `tests/fixtures/hh_contract_sanitized.json` содержит лишь обезличенную мета-схему.

## Защита от ошибочных действий

- Dry-run действует до точного однократного opt-in.
- Лимиты по умолчанию: 5 откликов, 20 сообщений в сутки, 30 секунд между последовательными write-командами и общий детерминированный read-throttler.
- Opt-in, hard stop, лимит и интервал повторно проверяются в `BEGIN IMMEDIATE` перед каждым remote write; активные reservations учитываются в лимите.
- Вакансии и recruiter message IDs дедуплицируются в SQLite.
- Перед откликом всегда выполняется свежий preflight; write без подходящего `resume_hash` невозможен.
- Успешный HTTP status недостаточен: отклик и сообщение обязаны вернуть известный semantic receipt.
- Сетевой исход `status=0` для write считается неоднозначным и включает hard stop.
- 401, 403, 429, login redirect, CAPTCHA/challenge и schema drift включают постоянный hard stop.
- Неидемпотентные write-запосы не повторяются после неоднозначного исхода; chat outbox повторяет только тот же логический send с персистентным UUID.

## Запрещённые возможности

Не добавляйте Playwright, Selenium, CDP, DOM-селекторы, клики, stealth, proxy rotation, fingerprint-подмену, генерацию `x-gib-*`, CAPTCHA solving или воспроизведение защитных запросов из HAR. Не расширяйте bridge произвольными URL, методами, заголовками или JavaScript.

## Остаточный риск

Web-контракт hh.ru не является публично поддерживаемым API для соискателей и может измениться без уведомления. Даже консервативная автоматизация может привести к дополнительной проверке, временному ограничению или блокировке аккаунта. При неожиданном поведении сначала выполните `job-finder autonomy disable`, затем вручную проверьте аккаунт; не снимайте hard stop до выяснения причины.

При подозрении на утечку отключите расширение, замените pairing secret, отзовите ключ провайдера и не публикуйте HAR или содержимое Keychain в issue/чате.
